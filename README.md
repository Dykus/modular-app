# Модульное приложение для производства

Веб-приложение с модульной архитектурой для замены сетевой Excel-таблицы.
Несколько человек работают одновременно, никто никого не блокирует,
все изменения фиксируются в журналах, доступ разграничен ролями.

## Архитектура: ядро + модули

- **core/** — ядро: Flask, база данных (SQLAlchemy/SQLite), авторизация, AD-провайдер, реестр прав, настройки, журналы.
- **modules/** — подключаемые модули. Каждый самодостаточен (свои таблицы, страницы и права в `perms.py`).
  Включаются/выключаются галочками в «Настройках» без правки кода.
- **web/** — общий веб-интерфейс (шапка, меню, стили, темы, печать).
- **data/** — база данных `database.db` и резервные копии.

## Авторизация, роли, права

- Вход по логину и паролю; пароли хранятся хешем (необратимо).
- Роли — наборы прав (галочек); права объявляются модулями в `perms.py` и написаны человеческим языком.
  Системные роли: `admin` (суперпользователь), `manager`, `staff`, `viewer`; свои роли создаются в экране «Роли».
- Замки прав на каждой странице модуля; без права — страница отказа с объяснением.
- Меню фильтруется по правам роли.
- Safety-switch: флажок «Включить авторизацию» (выключен = открыто по сети, режим внедрения и аварийный выход).
- Блокировка подбора пароля, журнал входов (кто, когда, IP, источник, причина), аудит действий над пользователями.
- Защиты: нельзя трогать себя и последнего активного администратора; у `admin` неснимаемые системные права.

Первичный вход: `admin` / `admin123` (система обяжет сменить пароль).

## Active Directory

- Опциональный провайдер входа (галочка в Настройках, право `auth.security`): хост/порт, без TLS / StartTLS / LDAPS,
  Base DN, шаблон входа или поиск по фильтру, роль по умолчанию.
- Graceful-degradation: при недоступности AD локальные пароли работают как раньше (если включён fallback).
- Авто-provisioning: первый вход доменной учёткой создаёт локальную запись с ролью по умолчанию,
  имя и email подтягиваются из AD; доменные пароли локально не хранятся.
- Авто-перевод: совпадение локального пароля с AD-паролем переводит учётку на доменный источник.
- Кнопка «Проверить связь» в Настройках: пошаговая диагностика (библиотека → хост → TCP → TLS → bind → поиск).
- Требуется библиотека `ldap3` (`pip install ldap3`); без неё AD-раздел показывает предупреждение, остальное работает.

## Установка и запуск

Требуется Python 3.10+.

```
pip install -r requirements.txt
python run.py
```

Откройте в браузере адрес из консоли (по умолчанию http://localhost:5000).
Порт настраивается в `config.py` (`PORT`); если порт занят, берётся следующий свободный.
Доступ по локальной сети: `http://IP-машины:порт` (`HOST = "0.0.0.0"`).
Для боевого запуска поставьте `debug=False` в `run.py`.

## Резервные копии

Все данные — в `data/database.db`. Бэкап = копия файла при остановленном сервере, с датой в имени.
Восстановление = положить копию поверх `database.db` и запустить сервер. Подробности — в «Руководстве».

## Документация и регламент

- Справка и Руководство живут внутри приложения и обновляются установщиками автоматически.
- `python sync_docs.py` и `python sync_0XX.py` — повторное применение содержимого документации.
- Регламент: после каждого изменения обновляются журнал изменений, версии (если изменение видно людям),
  справка, руководство и этот README. Печатная версия руководства перепечатывается после крупных обновлений.

## Примечания

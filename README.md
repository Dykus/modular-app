# Модульное приложение для производства

Веб-приложение с модульной архитектурой для замены сетевой Excel-таблицы.
Несколько человек работают одновременно, никто никого не блокирует,
все изменения фиксируются в журналах, доступ разграничен ролями.

## Архитектура: ядро + модули

- **core/** — ядро: Flask, база данных (SQLAlchemy/SQLite), авторизация, реестр прав, настройки, журналы.
- **modules/** — подключаемые модули. Каждый самодостаточен (свои таблицы, страницы и права в `perms.py`).
  Включаются/выключаются галочками в «Настройках» без правки кода.
- **web/** — общий веб-интерфейс (шапка, меню, стили, темы, печать).
- **data/** — база данных `database.db` и резервные копии.

## Модули

| Модуль | Адрес | Назначение |
|---|---|---|
| Задачи отдела (feedback) | `/feedback` | Трекер хотелок сотрудников со статусами и историей |
| Производство (production) | `/production` | Учёт под реальную Excel-таблицу (заполняется) |
| Журнал изменений (changelog) | `/changelog` | Лента «добавлено / исправлено / изменено / удалено», экспорт CSV |
| Версии (versions) | `/versions` | Релизы, страница «О программе», текущая версия в футере |
| Справка (help) | `/help` | Редактируемая документация по категориям |
| Руководство (manual) | `/manual` | Руководство по эксплуатации + версия для печати |
| Настройки (settings) | `/settings` | Вкл/выкл модулей, тема, авторизация, пороги блокировки |

## Авторизация, роли, права

- Вход по логину и паролю; пароли хранятся хешем (необратимо).
- При первом входе система обязывает сменить пароль.
- Блокировка подбора пароля: после N неудач подряд вход замирает на M минут (N и M настраиваются).
- **Роли** — наборы прав (галочек). Права объявляются модулями в `perms.py` и написаны человеческим языком.
  Системные роли: `admin` (суперпользователь), `manager`, `staff`, `viewer`; свои роли создаются в экране «Роли».
- **Замки прав**: каждая страница модуля закрыта декоратором права; без права — страница отказа с объяснением, какого права не хватает.
- Меню фильтруется по правам роли: человек видит только доступные разделы.
- **Safety-switch**: флажок «Включить авторизацию» в Настройках. Выключен — система открыта по сети (режим внедрения и аварийный выход). Включён — всё закрыто по умолчанию.
- Журнал входов (кто, когда, с какого IP, причина отказа) и аудит действий над пользователями.
- Защиты: нельзя трогать себя и последнего активного администратора; у `admin` неснимаемые системные права.

Первичный вход: `admin` / `admin123` (система обяжет сменить пароль).
Тестовая учётка `test_viewer` / `test1234` удаляется в экране «Пользователи».

## Установка и запуск

Требуется Python 3.10+.

```
pip install -r requirements.txt
python run.py
```

Откройте в браузере адрес из консоли (по умолчанию http://localhost:5000).
Порт настраивается в `config.py` (`PORT`); если порт занят, приложение само возьмёт следующий свободный и напишет об этом.
Доступ по локальной сети: `http://IP-машины:порт` (`HOST = "0.0.0.0"` в `config.py`).

Для боевого запуска поставьте `debug=False` в `run.py`.

## Резервные копии

Все данные — в `data/database.db`. Бэкап = копия файла при остановленном сервере, с датой в имени.
Восстановление = положить копию поверх `database.db` и запустить сервер. Подробности — в «Руководстве».

## Документация и регламент

- Справка и Руководство живут внутри приложения и обновляются установщиками автоматически.
- `python sync_docs.py` — повторное применение содержимого документации (статьи справки обновляются всегда).
- Регламент: после каждого изменения обновляются журнал изменений, версии (если изменение видно людям),
  справка, руководство и этот README. Печатная версия руководства перепечатывается после крупных обновлений.

## Структура папок

```
modular-app/
├── config.py            # порт, хост, путь к БД
├── run.py               # точка входа, автоподбор порта
├── sync_docs.py         # синхронизация документации
├── requirements.txt
├── core/                # ядро: app, auth, permissions, registry, models, seed
├── modules/             # feedback, production, changelog, versions, help, manual, settings
├── web/                 # общий интерфейс: templates/, static/ (включая print.css)
└── data/                # database.db (SQLite), бэкапы
```

## Примечания

- Интерфейс в браузере — на русском; служебный вывод установщиков в консоли — латиницей
  (консоль Windows портит кириллицу при выводе).
- Паролей по сети нет: сеть доверенная, но каждое действие пишется в журнал с именем.
